# Cognitive Forecasting Agent V1：从零到当前实现

> 面向第一次接触 Agent 开发的同学。本文描述截至 2026-11-04 的仓库实现和已经保存的运行记录。先读本篇建立全局认识，再按文中的文件顺序阅读代码。项目需求原文见 [prompt.md](../prompt.md)，运行命令见 [README.md](../README.md)，逐次开发和验收记录见 [PROGRESS.md](../PROGRESS.md)。

## 1. 一句话说明项目

用户提出“OpenAI 在 2026 年 12 月 31 日的私募估值落在哪个区间”。Agent 主动规划研究、搜索真实资料、整理可追溯证据、提出并审查因果假设，最后由确定性的 Python 数值程序计算每个区间的概率、生成报告并保存运行历史。

这里的 Agent 是**由状态、工具和控制流程组成的程序**。大语言模型（LLM）是其中一个工具；它并不单独决定最终数字。研究对象是 OpenAI，但课程重点是认知智能工作流，不是建立已经校准的金融交易模型。

### 先分清四件事

| 名称 | 含义 | 本项目中的例子 |
|---|---|---|
| 预测题目 | 要回答什么 | 2026-12-31 终点估值区间 |
| 观测指标 | “估值”具体取哪个数据源、哪个字段 | NPM OpenAI 数据页的 `latest_npm_price.implied_valuation`，单位美元 |
| 估值锚点 | 从可追溯的最新观测出发 | 保存的 2026-11-02 NPM 观测约 1.263746 万亿美元 |
| 预测结果 | 在显式假设下得到的未来分布 | 各区间概率、中位数、模型 90% 区间 |

Polymarket 只提供题目灵感。本项目预测**目标日期的终点区间**，不是“此前是否曾触及某阈值”的路径事件。区间由研究者定义，目前为 `<500B`、`500–750B`、`750–1000B`、`1000–1250B`、`1250–1500B`、`≥1500B`，单位均为十亿美元，边界左闭右开。`price` 是美元/股，不能当作公司整体估值。

## 2. 开始前需要懂的最少概念

1. **API**：程序通过 HTTP 请求调用外部服务。本项目调用 Tavily 搜索、兼容 OpenAI 格式的千问/DeepSeek 聊天接口、Embedding 接口，以及 NPM 官方页面使用的公开数据接口。
2. **结构化输出**：要求 LLM 返回符合 JSON 结构的数据。Pydantic 校验字段类型、枚举、数值范围；不合格的回复只允许一次付费修复请求，仍不合格则保存失败。
3. **状态（state）**：每一步得到的问题、搜索结果、证据、假设、预算和错误都放进 `CognitiveState`。状态会持久化，下一步从它读取，不依赖聊天上下文“记住”。
4. **工具调用**：搜索、抓 NPM 观测、调用模型、向量化、读写数据库、模拟概率，都是可检查的工具操作。
5. **RAG**：先从外部资料中取回与问题有关的证据，再把证据交给模型推理。这里使用 SQLite 保存证据、FAISS 排序检索。
6. **启发式概率**：通过明确的参数和随机模拟得出数字。它可复算，但参数未用历史结算数据校准，不能把概率说成已验证的预测准确率。

## 3. 从需求到 V1 的开发顺序

项目实际按 M1 → M2 → M3 → M4 逐步建设。初学者复现时也建议按此顺序；每完成一层，就保留可运行的最小闭环。

| 阶段 | 要解决的问题 | 主要成果 |
|---|---|---|
| M1：定义任务和最小闭环 | 数据结构、配置、搜索与 LLM 怎么接、概率怎么表示 | CLI、Pydantic 模式、Tavily/LLM 适配器、基准模拟、离线 demo |
| M2：认知研究循环 | Agent 如何主动研究、记忆、反证、补查 | LangGraph 状态图、SQLite、Embedding/FAISS、因果假设、独立审查、有限循环 |
| M3：数值预测与解释 | 怎么把证据变成可重放的区间分布 | 估值锚点选择、事件调整、蒙特卡洛、报告、数值复算 |
| M4：交互和验收 | 普通用户如何操作，失败如何追踪 | Streamlit 四页界面、后台 LIVE 作业、历史对比、测试和运行归档 |

期间口径从融资估值代理、Forge 讨论，最终调整为用户指定的 NPM 隐含公司估值。早期运行报告保留原口径，不会被改写成 NPM 结果。这也是为什么规则、来源和运行快照必须记录在每条预测里。

## 5. 一次 LIVE 预测如何流动

```text
用户问题 + 规则 + 预算
         │
         ▼
ParseQuestion → PlanResearch → Search → ProcessEvidence → RetrieveMemory
                                      ▲                          │
                                      └─ 检查缺口 ← Critique ← Reason
                                                           │
                                                           ▼
                  UpdateBelief → GenerateForecast → GenerateReport → SaveRun
```

控制器在 `core/controller.py`。每个节点完成后把更新的 `CognitiveState` 写入 SQLite 与 JSON 检查点；失败也保留状态和警告。研究最多按 `config/settings.yaml` 的次数循环，不会无限搜索。以下按一次实际运行说明。

### 第 1 步：解析预测任务

入口有两种：命令行 `main.py`，或 Streamlit 页面 `app/streamlit_app.py`。`core/task_parser.py` 从问题中识别 OpenAI、目标日期、指标与显式区间；`core/config.py` 读取 YAML 规则并验证。冲突的日期、混用平台、无单位区间、路径事件会在付费调用前拒绝。当前目标时区为 `America/New_York`，目标是 2026-12-31 23:59:59 美东时间。

关键文件：`config/market_rules.yaml` 定义观测指标、边界、结算处理；`config/settings.yaml` 定义搜索、模型、成本和数值参数。规则与参数会进入报告快照，避免日后改配置导致历史结果失去解释。

### 第 2 步：规划研究

`perception/research_planner.py` 给 LLM 当前问题、规则和已有证据，要求返回 `ResearchPlan`：每项有研究问题、理由、优先级、建议查询和预期信息。确定性规则还保证首次研究覆盖融资、收入和成本等重要方向，并优先寻找指定口径的估值。计划最多 8 项；Pydantic 拒绝越界优先级。

### 第 3 步：获取真实资料

`perception/search_client.py` 将查询发给 Tavily。保存标题、URL、来源、发布时间、检索时间、正文和原始查询；查询中的 `site:` 变成 API 域名过滤。`perception/npm_official.py` 另行抓取 NPM 官方 OpenAI 数据页实际使用的公开接口，保存响应快照，并把 `implied_valuation` 和 `price` 分开。每次请求之前由 `core/budget.py` 预留调用次数和估计费用。

**时间有三个不同含义**：`event_at` 是事件或价格的观测日期，`published_at` 是资料可公开时间或明确标记的抓取代理时间，`retrieved_at` 是本系统实际拿到资料的时间。不能把今天抓到的旧报价说成今天的新报价。NPM 锚点要求观测距信息截止不超过 14 天。

### 第 4 步：从文档抽取证据

`perception/evidence_extractor.py` 先用狭义规则解析可信的官方报价、日期及已完成融资，再让 LLM 处理其余文档。每条 `Evidence` 保留原文、精确支撑引句、来源 URL、类别、事实/预测/传闻性质、可信度、相关度、方向、事件时间与单位。程序检查引句是否真的出现在原文中、美元和数量级是否一致、公司整体估值是否误用了每股价或融资金额。单条不合格证据被隔离并记原因。

LLM 可能返回错误的枚举。例如曾返回 `claim_kind="reported claim"`。当前只把这个模糊标签归为 `unknown`，不自动认定“事实已发生”。这说明**模型输出必须当作待检查数据**。

### 第 5 步：保存和检索记忆

`memory/evidence_store.py` 将证据、运行与节点快照存 SQLite；证据按 ID 去重，LIVE 与 DEMO 分离。`memory/vector_store.py` 对符合时间条件的证据做向量化，用 FAISS 内积检索相关资料；还保护最新估值锚点和不同因素代表证据，避免相似度排序把关键资料全部挤掉。LIVE 的向量 API 有预算和缓存；DEMO 使用字符向量，因此无需外部服务。

向量检索回答的是“哪些证据值得送入下一步”，不是“哪些证据必然真实”。来源真实性和数字口径继续由规则与审查判断。

### 第 6 步：因果推理

`reasoning/causal_reasoner.py` 要求 LLM 根据证据 ID 生成 `Hypothesis`：事件、至少两段机制、正负方向、反论点、不确定性、是否可能已被价格计入。`causal_relations` 记录机制路径。它是可追溯的**假设**，不是从观察数据严格识别的因果效应。模型不能凭空引用不存在的证据 ID，也不负责直接写最终概率。

### 第 7 步：独立审查与必要补查

`reasoning/critic.py` 再用一次独立 LLM 调用审查证据和假设，列出接受、争议、结算指标失效和信息缺口。Python 再执行去重、日期、证据 ID 和冲突检查。不同日期的 NPM 观测是时间序列，不能当成同一事件的冲突报价；相同日期若官方估值数值不一致，仍保留争议。`reasoning/coverage.py` 要求至少两个来源域名、三类因素以及有依据的正负方向；`reasoning/gap_detector.py` 在预算范围内决定是否补搜。

曾有一条 LIVE 因审查把 10 月 29 日和 11 月 2 日 NPM 观测混为冲突而报 `MissingAnchor`。修复后从审查节点沿用原 run_id、证据和累计预算续跑。这是状态与断点设计的实际作用。

### 第 8 步：选择锚点并更新信念

`belief/baseline.py` 在**已接受**的证据中选择与配置口径完全一致、日期可靠且未过期的估值。当前 NPM 只能使用对应官方页面及其数据接口的整体 `implied_valuation`；不会拿 Forge、融资估值或美元/股替代。若缺锚点，或 `belief/settlement.py` 判定有可靠证据表明私募指标失效，就拒绝生成概率。

`belief/scenario_updater.py` 把接受的独立事件映射成受限的对数调整。锚点当日及此前的信息默认已体现在报价中，不再重复加价；传闻、评论或性质未知的事件不作数值调整。v1.4 对有来源、有方向机制、但结果尚未实现的未来预测加入零均值兑现风险，用于改变终点分布形状，方法与离线对照见 [信念更新修订](BELIEF_UPDATING_V14.md)。之后经 `belief/distribution.py` 用 NumPy 按固定随机种子生成 50,000 个未来估值样本，按配置区间计数得到概率。

简化公式：

```text
T = (目标时点 - 锚点时点) / 年
log(基准样本 / 锚点) = 年化对数漂移 × T + 综合波动 × 标准正态噪声
更新后样本 = 基准样本 × exp(受约束事件调整 × 情景倍率)
某区间概率 = 落入该区间的样本数 / 总样本数
```

综合波动含年度波动、锚点年龄等显式不确定性；融资代理模式另有代理误差。事件情景倍率为 0、1、2，权重为 0.25、0.5、0.25。默认年度对数波动 0.5、漂移 0、单事件对数幅度 0.025、总幅度上限 ±0.25。**这些是 V1 的可见启发式参数，尚未历史校准。** 固定种子使同一证据、规则和配置可精确复算；这只证明计算可重现，不证明预测准确。

### 第 9 步：输出和持久化

`forecasting/forecast.py` 生成各区间概率、中位数和模型 90% 区间；`forecasting/report.py` 输出 Markdown、JSON、SVG 和 Plotly HTML。`memory/evidence_store.py` 保存最终 `completed` 或 `failed` 状态。`evaluation/history.py` 仅在目标、指标、区间等兼容时比较两次记录，解释概率、锚点、证据和事件调整的变化。

## 6. 运行记录长什么样

每次运行有唯一 `run_id`。以已保存的 `3b5d47809dbb4830821e8fc36989a05f` 为例：它最初因审查去重错误失败，修复后从 `Critique` 续跑，最终 `completed`。其 NPM 锚点来自 2026-11-02 观测，约 1263.746 USD billion；模型中位数约 1262.393 USD billion。完整报告在 `reports/runs/live/<run_id>/report.md`，同目录含 `state.json`、`forecast.json`、图表及 `verification.json`。这些是那次运行的历史快照，不能自动代表今天最新报价。

`scripts/verify_run.py` 不访问网络，读取存档的规则、配置与证据，重新计算并核对预算、来源引句、时间隔离、概率和、完整产物、精确数值重放。该 run 的所有检查通过；独立复算不能验证模型参数的现实准确率。

## 7. DEMO 与 LIVE 的差别

| 项目 | DEMO / SYNTHETIC | LIVE |
|---|---|---|
| 数据 | 程序构造的合成样例 | 实际 API 响应与保留的原始来源 |
| 外部费用 | 不调用真实搜索、LLM、Embedding | 可能产生供应商费用 |
| 用途 | 展示流程、测试 UI 与代码 | 形成有来源的真实研究记录 |
| 时间 | 可指定合成截止时间 | 只允许当前研究；不可把实时搜索当历史回测 |
| 证据与历史 | 与 LIVE 按 `mode` 隔离 | 只读取 LIVE 证据 |

“合成”表示为了演示而编造的测试输入，页面已明确标识。LIVE 也可能失败：密钥/网络错误、模型 JSON 不合格、证据不足、NPM 锚点过期或预算耗尽时，系统保存失败而不生成伪概率。

## 8. 从零复现的操作步骤

在 Windows PowerShell 中进入项目目录。已有 `.venv` 的本机可以跳过创建和安装；新电脑需要 Python 3.12 和联网安装依赖。

```powershell
cd D:\Desktop\openai_valuation_forecast
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m ruff check .
.\.venv\Scripts\python main.py --demo --as-of 2026-11-02T06:30:00+00:00
.\.venv\Scripts\python -m streamlit run app\streamlit_app.py --server.port 8502
```

最后一条命令启动本地网站，浏览器打开 `http://127.0.0.1:8502`；运行期间终端须保持打开。页面有“预测任务”“认知研究过程”“预测结果”“预测历史”四页。先用 DEMO 熟悉流程；LIVE 需要把自己的 Tavily 和 LLM 凭据放到本地 `.env`，按照 `.env.example` 填写，不要把密钥写入代码、文档或提交记录。LIVE 页面点击开始后，`app/jobs.py` 在独立 Python 子进程运行；历史页每 5 秒刷新状态。后台日志在 `data/jobs/<run_id>/`。

CLI 真实运行可用 `\.venv\Scripts\python main.py`。中断后可用 `--resume <run_id>` 沿用累计预算；明确要重新做证据处理或审查时分别使用 `--resume-from ProcessEvidence`、`--resume-from Critique`。续跑可能再次调用付费 API，并不保证外部请求只发生一次。

## 10. 讲解时需要诚实说明的边界

- NPM Price 是平台的指示性估计；系统预测的是 NPM 隐含公司估值，不是可保证成交的价格，也不等于其他平台或融资口径。
- 研究记录可追溯、数值可复算；这不等于已完成历史回测。真实参数校准、Brier score 等需要后续真实结算数据与严格历史资料隔离。
- LLM 的因果路径是有证据支持的研究假设，不能直接称为因果识别。审查可以指出缺口，不能保证资料全面。
- 报告可能包含续跑前的旧失败警告，应该同时看最终 `status`、`trace` 和验证结果。
- V1 没有公网部署和多用户认证。分享本地页面需同一局域网且主机持续运行；公开部署前要另做访问控制与密钥/费用隔离。

## 11. 给同学演示的讲解路线（约 25 分钟）
